## Open decisions for the owner

1. Minimum number of tries for interruption. The documents give the 95 percent target but no minimum.
2. Latency acceptance wording. The implementation applies the 90 percent rule to the total short request, and reports stage pass rates as diagnostics only. Confirm this reading.
3. Latency budget values are design targets from v9 6.4, used as written and not as release guarantees.
4. Whether a real-phone run with virtual glasses (in-app path only) counts as real phone evidence, or only as a simulator-link measurement. The validator accepts it as real phone evidence with the same-clock timing source, and the summary keeps it separate from transport latency.
5. Whether the importer should reject `latency_total` and `interruption` rows until the app can produce them. Today `SUPPORTED_MEASURES` accepts both, so a hand-made file with those measures is validated and summarised, although the app records neither. Changing this changes the validator contract; it was not changed in this pass.
