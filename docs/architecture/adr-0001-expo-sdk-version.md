# ADR-0001: Expo SDK version

Status: accepted, with a dated follow-up
Date: 2026-10-20 (decision revised the same day)
Requirement: Engineering Standards 1 (stack), Goal section 10A, decision G46

## Context

G46 approves an Expo cross-platform app (iOS and Android) with development builds, never Expo Go. The Standards require the Expo SDK to be pinned and upgraded at most once per SDK release, through `npx expo install --fix` and the full test suite.

The workspace enforces a minimum release age for npm packages (supply-chain cooldown, 24 hours at the time of this decision). Expo SDK 58 was released in several patches on 2026-10-19, inside that cooldown.

## Options considered

1. Latest published Expo SDK 58 patch (58.0.16, published 2026-10-19). Rejected for now: it falls inside the cooldown.
2. Pin the newest SDK 58 patch outside the cooldown (58.0.14), and let Expo's own tooling align the rest later.
3. Relax the cooldown with exemptions for the Expo packages. Rejected: it weakens a supply-chain control (Standards 5). The Expo installer tried to add such exemptions automatically; those were reverted.

## Choice

Option 2. `expo@58.0.14` is pinned exactly. `expo-router@58.0.23` and `expo-updates@~58.0.15` (resolved to 58.0.17) were installed; both were published before the cooldown cut-off.

## Known limitation

`npx expo install --check` reports that `expo@58.0.14` expects `~58.0.16` of the core packages, and `expo-router@58.0.23` expects `~58.0.24`. Both are inside the cooldown today. The mismatch is recorded in `blocker.txt` as an OPEN agent task, not accepted as a permanent state.

## Follow-up (dated)

After 2026-10-20 14:40 UTC (more than 24 hours after 58.0.16 was published), re-run `npx expo install --check`. Move the SDK to the patch the tooling expects. Do not add exemptions to the cooldown. Then re-run the full test suite and record the result in `PROGRESS.md`.

### Follow-up result (2026-10-24)

Completed. The release-age check passed for the target versions (published 2026-10-19 to 2026-10-21). `expo` is now pinned to `58.0.17`, and `expo-constants`, `expo-linking`, `expo-router`, `expo-updates` and `jest-expo` moved to the patches the tooling expects. `npx expo install --check` reports "Dependencies are up to date". The cooldown was not relaxed and no exemptions were added. The full test suite passes.

## Consequences

- The SDK version is an exact pin, not a range, for `expo`.
- Native folders (`ios/`, `android/`) are generated by Continuous Native Generation and never hand-edited.
- No native build has been produced or run yet. Development builds need an owner-held Expo account and an EAS build (see `blocker.txt`).
