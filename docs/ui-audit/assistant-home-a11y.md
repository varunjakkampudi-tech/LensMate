# Assistant and Home Accessibility Audit

**Evidence level:** Static review only. No VoiceOver, TalkBack, emulator, or 200% text-scale run was performed.

**Scope:** `apps/mobile/app/assistant.tsx`, `apps/mobile/app/index.tsx`, and the directly imported UI components used by these screens (`src/ui/kit.tsx`, `src/ui/lang-picker.tsx`, and `src/ui/icon.tsx`).

The Engineering Standards owner document (not present in this repository), section 3, requires accessible labels and roles, touch targets of at least 48 dp, information not conveyed by colour alone, and usable text at 200% scaling.

## Review notes

- The primary interactive controls in both routes have explicit roles and labels. The assistant status has polite live text, the provider badge has an accessibility label, and the home tiles expose link roles.
- The home tiles, provider badge, and spend bar include text or numeric context in addition to colour; no separate colour-only defect was found there.
- Text styles do not disable font scaling, which is appropriate, but this static review cannot establish usable layout at 200%. The fixed `maxHeight: 120` on the multiline question input (`apps/mobile/app/assistant.tsx:435-455`) and the compact header/provider row (`apps/mobile/app/assistant.tsx:214-268`) should be checked at 200% on both platforms for clipping, overlap, and reachable controls.
